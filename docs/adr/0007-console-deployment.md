# 7. Deploying the console

Status: accepted

## Context

[llm-gateway-console](https://github.com/sillykea/llm-gateway-console) lets
admins create and revoke gateway API keys and set budgets, and gateways pull
the key list from it. It stores keys (as SHA-256 hashes) and an append-only
audit log in files, with one writer. The platform needs to run it next to the
gateway without weakening what the gateway already guarantees.

## Decision

- **One replica, as a StatefulSet** with a gp3 volume for `/data`. A second
  replica would mean a second writer to the same files; the console's own
  ADR rules that out until the store moves to Postgres.
- **Gateways are fail-static.** If the console is down or redeploying,
  gateways keep the last key set they fetched. A gateway that has never
  synced reports not ready, so the console syncs in an earlier Argo CD wave
  (0) than the gateway (1).
- **Secrets, all through External Secrets** and the environment's KMS key:
  - `CONSOLE_SYNC_TOKEN`: generated by Terraform, read by both the console
    and every gateway.
  - `CONSOLE_SESSION_SECRET`: generated by Terraform.
  - `users.json` (usernames, roles, password hashes): written by hand with
    the AWS CLI, so password hashes never appear in Terraform state.
- **Two ports, two audiences.** 8090 (UI and API) takes traffic from inside
  the VPC. 8091 (`/internal/keys`) accepts only gateway pods, enforced by
  NetworkPolicy on both sides, and is never put behind the ingress.
- **No public ingress by default.** Session cookies are `Secure`, so the
  console is reached with `kubectl port-forward` (http://localhost counts as
  secure) or an internal ALB that requires an ACM certificate.

## Consequences

- A console restart has no effect on traffic; key changes made during it
  apply once it's back (within the gateways' 30-second refresh).
- Losing the volume loses the key list and audit log. EBS snapshots
  (AWS Backup) are the recovery path; gateways keep serving the last keys
  until new ones are issued.
- Moving the store to Postgres (RDS) would allow more replicas and point-in-
  time recovery. That is the next step if the console becomes critical.
